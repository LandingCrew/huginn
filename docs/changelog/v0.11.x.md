# Changelog - v0.11.x Series

## v0.11.7 - HUD Visibility Manager

**Release Status:** Complete

### Auto-Hide Widget in Game Menus
- **Problem:** IntuitionMenu used `kAlwaysOpen` with no auto-hide logic. The widget rendered on top of inventory, map, crafting, dialogue, and all other full-screen menus — visually cluttering the screen.
- **Fix:** New `HudVisibilityManager` listens for `MenuOpenCloseEvent` and toggles `_root._visible` on the Scaleform movie based on `RE::UI::GameIsPaused()`.
  - Every menu with `kPausesGame` flag (inventory, map, crafting, dialogue, barter, lockpicking, etc.) increments the `numPausesGame` counter — widget hides when counter > 0
  - Console and Favorites don't set `kPausesGame` — widget correctly stays visible during those overlays
  - Visibility change deferred to UI thread via `SKSE::GetTaskInterface()->AddUITask()` for thread safety
  - Early-return when `IntuitionMenu::GetSingleton()` is null (skips all startup menu events before a game loads)
- **Design note:** Originally planned to use `ControlMap::contextPriorityStack` (TrueHUD's pattern), but the `BSTArray` at offset `0x100` has an incorrect layout for Skyrim 1.6.1170 — the internal data pointer was consistently `0x67` (garbage), causing an access violation. `RE::UI::GameIsPaused()` is a virtual method call that avoids all raw memory offset issues.
- **New class:** `HudVisibilityManager` — singleton `BSTEventSink<MenuOpenCloseEvent>`, registered once at `kDataLoaded`
- **New method:** `IntuitionMenu::SetVisible(bool)` — toggles `_root` DisplayInfo visibility (preserves all widget state for instant restore)
- **Files:** `src/ui/HudVisibilityManager.h` (new), `src/ui/HudVisibilityManager.cpp` (new), `src/ui/IntuitionMenu.h`, `src/ui/IntuitionMenu.cpp`, `src/Main.cpp`

## v0.11.6 - Intuition Widget Tuning & Wheeler Page Sync

**Release Status:** Complete

### Wheeler ↔ IntuitionMenu Bidirectional Page Sync
- **Problem:** Keyboard page cycling (keys 4/5) updated IntuitionMenu but not Wheeler's active wheel. Conversely, scrolling Wheeler wheels didn't persist the page choice — IntuitionMenu snapped back when Wheeler closed.
- **Fix (Keyboard → Wheeler):** Cycle callback in `Main.cpp` now calls `WheelerClient::SetActivePage()` after `SlotAllocator::NextPage/PreviousPage()`. No-op when Wheeler is not installed.
- **Fix (Wheeler → SlotAllocator):** `UpdateLoop.cpp` now calls `slotAllocator.SetCurrentPage()` when it detects Wheeler's active page differs, so the choice persists after Wheeler closes.
- **New method:** `WheelerClient::SetActivePage(size_t pageIndex)` — maps page index to Wheeler wheel index via `GetWheelIndexForPage()`, calls `SetActiveWheelIndex()`. Returns false gracefully if Wheeler not connected.
- **Files:** `WheelerClient.h`, `WheelerClient.cpp`, `Main.cpp`, `UpdateLoop.cpp`

### Dynamic Background Width
- **Problem:** Background width was fixed at `SLOT_WIDTH + PADDING*2` (240px). Long names like "Potion of Invisibility (Fair)" overflowed the panel.
- **Fix:** Background auto-sizes to fit the widest visible slot name:
  - Slot `itemName` TextFields use `autoSize = "left"` (no longer clipped)
  - `recalcWidth()` scans all visible slots, computes `NAME_X + maxTextWidth + PADDING*2 + gutter`
  - Floor of `SLOT_WIDTH + PADDING*2` prevents collapse on short names
  - `resizeBackground()` called from both `setSlotCount()` and `applyItemContent()`
- **New state:** `_bgWidth` instance variable tracks current background width
- **Files:** `src/swf/Intuition.as`

### INI-Configurable Child Element Opacity (fAlphaChild)
- **Problem:** Secondary elements (page label, inactive dots) used hardcoded alpha=70, not configurable
- **Fix:** Full INI → C++ → AS2 pipeline:
  - `IntuitionDefaults::CHILD_ALPHA = 70.0f` compile-time default
  - `IntuitionSettings` loads `fAlphaChild` from `[Widget]` section
  - Constructor pushes to AS2 via `m_widget.Invoke("setChildAlpha")`
  - AS2 `_childAlpha` variable replaces all hardcoded 70 values
- **Files:** `IntuitionSettings.h`, `IntuitionSettings.cpp`, `IntuitionMenu.cpp`, `Intuition.as`, `Huginn.ini`

### Confirm Pulse C++ Wiring
- **Problem:** AS2 `setConfirmPulse()` method existed but was never called from C++ — always defaulted to enabled
- **Fix:** Full INI → C++ → AS2 pipeline:
  - `IntuitionDefaults::CONFIRM_PULSE = true` compile-time default
  - `IntuitionSettings` loads `bConfirmPulse` from `[Widget]` section
  - Constructor pushes to AS2 via `m_widget.Invoke("setConfirmPulse")`
- **Files:** `IntuitionSettings.h`, `IntuitionSettings.cpp`, `IntuitionMenu.cpp`, `Huginn.ini`

### Page Indicator Labels
- **Problem:** Page dots gave no indication of which page was active beyond dot highlighting. Wheeler wheels show names but IntuitionMenu did not.
- **Fix:** Active dot now displays an inline page name label (e.g., `Smart`, `Inventory`):
  - Dynamic layout with running `curX` cursor — label inserted after active dot, remaining dots flow after
  - Label uses `autoSize = "left"` for variable-width text, `_childAlpha` opacity
  - Page indicator strip left-justified at 2px from widget edge
- **Files:** `src/swf/Intuition.as`

### Invisible Inactive Dots Fix
- **Problem:** Inactive page dots were nearly invisible — `beginFill(0xFFFFFF, 80)` × `_alpha = 30` = 24% effective opacity
- **Fix:** Changed inactive dot alpha from hardcoded `30` to `_childAlpha` (default 70), giving 56% effective opacity
- **Files:** `src/swf/Intuition.as`

### Layout Tuning
- `PADDING` increased from 6 to 10 for slot content (breathing room inside background panel)
- Page indicator pips positioned at 2px from edge (compact, separate from slot padding)

## v0.11.5 - Intuition Scaleform Widget MVP

**Release Status:** Complete

### Scaleform HUD Widget (IntuitionMenu)
- Native Skyrim HUD via `RE::IMenu` subclass — replaces ImGui for player-facing display
- `IntuitionMenu` (C++) loads `Huginn/Intuition.swf` via `BSScaleformManager`
- `Intuition.as` (AS2) renders up to 10 classified slots with type-colored text
- SWF stage 1280x720 (Skyrim's virtual resolution) with kShowAll scale mode
- HUD-style flags: `kAlwaysOpen`, `kRequiresUpdate`, `kAllowSaving`

### Live Data Wiring
- Update loop bridges slot assignments to IntuitionMenu (same data as Wheeler)
- `MapSlotContentType()` converts `SlotContentType` (10 values) → `IntuitionSlotType` (9 values)
- Slot count, page indicator, and urgent status wired from update loop
- IntuitionMenu tracks Wheeler's active page when Wheeler is open

### Slide Reveal Animation
- Content change triggers slide-out (old text fades up 14px, 300ms) then slide-in (new text rises with ease-out, 350ms)
- Change detection via `_currentName[]` — only actual name changes trigger animation
- First population applies directly with no animation

### Refresh Flash
- When any slot changes, all idle slots do a `sin(PI*t)` alpha dip (500ms)
- Proportional to each slot's base alpha (NoMatch slots flash less)

### Urgent Pulse
- Override slots do a 2-second sine cycle (60-100% alpha)
- Driven by `setUrgent(index, active)` from C++

### Confirm Pulse
- Same-content re-evaluation triggers subtle alpha dip (200ms)
- Per-slot cooldown (2s) prevents over-pulsing
- Toggleable via `setConfirmPulse(enabled)` from C++

### INI Configuration ([Widget] section)
- `bEnabled` — enable/disable widget
- `fPositionX`, `fPositionY` — screen percentage positioning (0-100)
- `fAlpha` — overall widget opacity (0-100)
- `fScale` — widget scale percentage (50=half, 100=native, 200=double)
- Position converts screen % → stage coordinates accounting for kShowAll viewport math

### C++-Driven Animation Tick
- Scaleform GFx in Skyrim doesn't reliably fire AS2 `onEnterFrame`
- `AdvanceMovie()` calls `tick(dt)` via `GFxValue::Invoke` every render frame
- Delta time from game engine ensures frame-rate-independent animations

## v0.11.4 - Wheeler Code Review Fixes

**Release Status:** Complete

Address 8 actionable issues (3 critical, 5 important) from Wheeler subsystem code review.

### Critical Fixes

#### Use-After-Free on Wheel Labels + Leaked Wheeler Resources
- **Problem:** `CreateRecommendationWheels()` called `m_pageWheels.clear()` without first calling `DeleteManagedWheel()`, freeing `wheelLabel` strings while Wheeler may still hold `c_str()` pointers, and leaking Wheeler-side resources (orphan wheels accumulate across save/load cycles)
- **Fix:** Extracted `DestroyRecommendationWheels()` helper that iterates `m_pageWheels`, calls `DeleteManagedWheel()` for each valid index, then clears the vector. Replaced both bare `.clear()` calls.
- **Files:** `src/wheeler/WheelerClient.h`, `src/wheeler/WheelerClient.cpp`

#### Data Races on m_wheelVisible and m_currentPage
- **Problem:** `m_wheelVisible` written from Wheeler callback thread, read from update thread without synchronization. `m_currentPage` written from input thread, read from update thread.
- **Fix:** Changed `m_wheelVisible` to `std::atomic<bool>` and `m_currentPage` to `std::atomic<size_t>`. Both are single-writer/multi-reader, so atomics are sufficient (no mutex needed).
- **Files:** `src/wheeler/WheelerClient.h`, `src/slot/SlotAllocator.h`

### Important Fixes

#### Wheel Ownership Validation
- **Problem:** `UpdatePageWheel()` could call Wheeler API on a wheel that was deleted by another mod or invalidated by index shift
- **Fix:** Added `IsManagedWheel()` guard at top of `UpdatePageWheel()`. If wheel is no longer managed, marks it invalid (`wheelIndex = -1`) and returns early.
- **Files:** `src/wheeler/WheelerClient.cpp`

#### AddItemByFormID Infinite Retry Loop
- **Problem:** When `AddItemByFormID` fails (e.g., mod removed, FormID invalid), it retried every frame (~100ms) indefinitely, generating ~10 warnings/second in the log
- **Fix:** Added per-slot `slotRetries` counter (in `PageWheel` struct). After 3 failures for the same FormID+UniqueID, caches the failure and stops retrying. Counter resets when FormID changes. Demoted log from `warn` to `debug`.
- **Files:** `src/wheeler/WheelerClient.h`, `src/wheeler/WheelerClient.cpp`

#### Unnecessary ClearEntry API Calls
- **Problem:** `ClearEntry` was called even when the slot was already empty (`cachedFormID == 0`)
- **Fix:** Guard `ClearEntry` with `if (cachedFormID != 0)` check
- **Files:** `src/wheeler/WheelerClient.cpp`

#### Re-Entrancy Documentation
- Added documentation comment block above callback trampoline section explaining the constraint: never call Wheeler API while holding `m_callbackMutex`
- **Files:** `src/wheeler/WheelerClient.cpp`

#### Narrowed Exception Handling in WheelerSettings
- **Problem:** `ParseWheelPosition()` used `catch(...)` which swallows all exceptions including logic errors
- **Fix:** Replaced with specific `catch(const std::invalid_argument&)` and `catch(const std::out_of_range&)` — the only exceptions `std::stoi` can throw
- **Files:** `src/wheeler/WheelerSettings.cpp`

### Other Fixes

#### UtilityScorerDebugWidget Version String
- **Problem:** Window title hardcoded as `"Utility Scorer [v0.9.0]"` while all other debug widgets use `Huginn::VERSION_STRING`
- **Fix:** Changed to `std::format("Utility Scorer [v{} DEBUG]", Huginn::VERSION_STRING)` matching pattern in CacheDebugWidget, StateManagerDebugWidget, and RegistryDebugWidget
- **Files:** `src/ui/UtilityScorerDebugWidget.cpp`

## v0.11.3 - Wheeler Weapon UniqueID Fix

**Release Status:** Complete

### Wheeler UniqueID Threading
- **Problem:** Wheeler's `AddItemByFormID(wheel, entry, formID, uniqueID)` requires a non-zero `uniqueID` for weapon/armor forms to identify specific inventory instances (same base weapon can have different enchantments/tempering). Huginn passed `0` for all items, causing Wheeler to reject weapons with error -6 (UnsupportedFormType).
- **Fix:** Thread `RE::ExtraUniqueID` through the full candidate pipeline:
  1. **WeaponData/ScannedWeapon** — Added `uint16_t uniqueID` field
  2. **ExtractWeaponMetadata()** — Extract `ExtraUniqueID` from extraList (same pattern as `ExtraCharge`)
  3. **RefreshCharges() / ReconcileWeapons()** — Propagate uniqueID when updating existing weapons
  4. **CandidateBase** — Added `uint16_t uniqueID` field + `GetUniqueID()` helpers
  5. **FromWeaponData()** — Copy `data.uniqueID` into candidate
  6. **SlotUtils::ExtractUniqueIDs()** — New parallel extractor (matches `ExtractFormIDs()`)
  7. **WheelerClient** — Thread `uniqueIDs` through all update methods; pass to `AddItemByFormID()`
  8. **Main.cpp** — Wire `ExtractUniqueIDs()` into Wheeler update call
- **Time-guard behavior:** During first ~500ms after load, `uniqueID=0` (extraLists not stable). After stabilization, `RefreshCharges()` populates uniqueID and Wheeler re-adds the weapon. Matches existing charge/favorite behavior.
- **Files:** `WeaponData.h`, `WeaponRegistry.h/.cpp`, `CandidateTypes.h/.cpp`, `ScoredCandidate.h`, `SlotUtils.h`, `WheelerClient.h/.cpp`, `Main.cpp` (10 files, 90 insertions)

## v0.11.2 - Weapon Slot Bug Fixes

**Release Status:** Complete

### Favorites Detection Race Condition
- **Problem:** `ReconcileWeapons()` was overwriting correct favorites with `false`
  - `RefreshCharges()` correctly detected favorites via ExtraHotkey
  - `ReconcileWeapons()` ran immediately after, couldn't detect favorites (timing guard)
  - It overwrote `isFavorited = sw.isFavorited` (false) on all weapons
- **Fix:** Only update favorites in `ReconcileWeapons()` when `safeToAccessExtraLists` is true
  - Added guard: `if (safeToAccessExtraLists) { invWeapon.isFavorited = sw.isFavorited; }`
- **Files:** `src/weapon/WeaponRegistry.cpp`

### Weapon Truncation Bug
- **Problem:** Weapons were being truncated by `maxCandidatesAfterFilter = 100`
  - Weapons gathered LAST in pipeline (after spells, potions, scrolls)
  - With 306 total candidates, weapons at positions 100+ were cut off
  - Incorrectly attributed to "deduplication" in logs
- **Fix:**
  1. Increased `maxCandidatesAfterFilter` from 100 to 500
  2. Added `std::partial_sort` by relevance before truncation (O(n log k))
  3. Fixed logging to distinguish dedup vs truncation losses
- **Files:** `src/candidate/CandidateConfig.h`, `src/candidate/CandidateFilters.cpp`

### Favorited Items Not Winning Relevance
- **Problem:** Non-favorited staves (3.0 relevance in combat) beat favorited swords (0.75)
  - `favoritedItemBonus = 1.5f` wasn't enough to overcome combat boost
- **Fix:** Increased `favoritedItemBonus` from 1.5 to 10.0
  - User-favorited items now almost always beat non-favorited items
  - Design: Explicit favorites represent user intent, should be respected
- **Files:** `src/candidate/CandidateConfig.h`

### New Features

#### ScanWeaponFavorites() Helper
- Added `ScanWeaponFavorites()` method to WeaponRegistry
- Mirrors `SpellRegistry::ScanSpellFavorites()` pattern
- Returns set of FormIDs for favorited weapons (ExtraHotkey detection)
- Respects 500ms extraLists stabilization guard
- **Files:** `src/weapon/WeaponRegistry.h`, `src/weapon/WeaponRegistry.cpp`

### Improved Logging
- **RefreshCharges:** Logs when favorites status changes per-weapon
- **RefreshCharges:** Summary log: "updated X weapon favorites (total now: Y)"
- **CandidateFilters:** Dedup logging now shows total candidates before/after
- **CandidateFilters:** Weapon filter log now shows: `afterFilter -> afterDedup -> out (dedup=X, trunc=Y)`

## v0.11.0 - Multi-Page Slot System

**Release Status:** Complete

### Multi-Page Slot Architecture
- **SlotSettings configuration system**
  - INI-based configuration (`Data/SKSE/Plugins/Huginn.ini` [Pages] section)
  - Up to 4 pages, 8 slots per page (configurable)
  - Per-slot configuration: classification, priority, wildcards, overrides
  - Default page 0 with 7 typed slots (Damage, Healing, Buffs, etc.)
- **SlotAllocator page management**
  - `SetCurrentPage()`, `NextPage()`, `PreviousPage()` methods
  - Page-aware slot allocation (fetches configs from SlotSettings at runtime)
  - Stateless allocation - no cached configs, always reads from SlotSettings
- **Keyboard integration**
  - Keys 4/5 wired to page cycling via InputHandler callback
  - Dynamic slot count per page reflected in widget
- **SpellRecommendationWidget updates**
  - Dynamic `m_activeSlotCount` based on current page
  - Page name displayed in header
  - Fixed key label collision (slots 3-7 use keys 6-0)

### Wheeler Multi-Page Integration
- One wheel per page (replaced fixed primary/alternate wheels)
  - `std::vector<PageWheel> m_pageWheels` structure
  - Dynamic wheel creation matching page configs
  - Wheel labels persist for Wheeler API lifetime (fixed dangling pointer bug)
- Per-page wheel updates
  - `UpdateRecommendationsForPage()` for cross-page updates
  - Wildcard flags properly propagated via `std::vector<bool>`
  - Fixed std::vector<bool> proxy reference quirk

### Wildcard System Generalization
- Generalized from hardcoded 3 slots to N slots
  - `std::array<WildcardSlot, MAX_WILDCARD_SLOTS>` (MAX=8)
  - Probability scaling: `P(slot i) = baseProbability * i` (capped at maxProbability)
  - Legacy compatibility: `GetSlot2Wildcard()`, `GetSlot3Wildcard()` still work
  - Configurable first-slot exclusion flag
- Legacy overload for backwards compatibility
  - `ApplyWildcards(rankedCandidates)` gets slot count from SlotAllocator

### Code Quality Fixes
- Thread safety: Static diagnostic variables -> `thread_local`
- Exception safety: SlotSettings builds config in temp vector before commit
- Bounds checking: WildcardManager::GetProbabilityForSlot validates slotIndex
