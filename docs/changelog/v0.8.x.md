### Candidate Generator MVP

Central orchestrator that combines state + all scanners -> filtered candidate list.

#### Core CandidateGenerator Class
- Central orchestrator for candidate generation pipeline (src/candidate/)
- Integrates StateManager, SpellRegistry, ItemRegistry, and all scanners
- Produces filtered candidate list for Utility Scorer
- Update loop integration (~100ms interval)

#### Candidate Data Structure
- FormID, item/spell metadata, source type (spell/potion/weapon/scroll/etc.)
- Pre-computed classification data (type, element, tags, archetype)
- Affordability check results (can cast? have item?)
- Relevance metadata (for context weight calculation)
- Deduplication key (prevent same item in multiple slots)

#### Scanner Integration
- SpellRegistry -> spell candidates
- PotionScanner -> potion candidates
- WeaponScanner -> weapon/arrow candidates
- ScrollScanner -> scroll candidates
- SoulGemScanner -> soul gem candidates (context: low weapon charge)
- Equipment pre-filtering (filter out already equipped spells/weapons)

#### Context Filtering Pipeline
- **Relevance filter**: Healing spells only when HP < 100%, Waterbreathing only underwater, etc.
- **Affordability filter**: Magicka cost check, item count check, weapon charge check
- **Equipped filter**: Filter out currently equipped spells and weapons
- **Cooldown filter**: Per-item cooldown tracking with configurable durations

#### Deduplication System
- Deduplication key generation (FormID + source type)
- Candidate list uniqueness enforcement
- Priority resolution when duplicates detected (higher utility wins)
