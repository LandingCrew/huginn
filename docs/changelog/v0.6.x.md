## v0.6.7 - Crosshair Stability

### Bug Fixes
- **Fixed target flickering outside combat** - NPCs (especially allies) rapidly appearing/disappearing when looking at them
  - Root cause 1: `PollTargets()` cleared ALL targets including primary/crosshair when not in combat
  - Root cause 2: No hysteresis for brief raycast misses at close range
  - Solution: Combat-exit now only clears secondary targets via `std::erase_if`, preserving primary crosshair target
  - Added sticky target hysteresis (300ms persistence for brief raycast failures)
  - Added edge case handling for negative time delta (save/load scenarios)

## v0.6.10 - Follower Tracking Bugfix

### Bug Fixes
- **Fixed follower detection only working when looking at follower** - Followers are now tracked at all times, not just during combat
  - Root cause: Follower scanning loop in `PollTargets()` was nested inside `if (inCombat)` block
  - Fix: Moved follower scanning outside the combat block with its own `processLists` check
  - Enables:
    - Healing recommendations before combat starts
    - Seeing injured follower status while exploring
    - Proactive healing when a follower takes environmental damage

### Files Changed
- `src/state/StateManager_Targets.cpp` - Restructured `PollTargets()` to scan followers independently of combat state

### Technical Details
The follower scanning block now runs unconditionally:
```cpp
// Before (BUG): Follower scanning inside combat block
if (inCombat) {
    // Enemy scanning...
    // Follower scanning... <- Only ran in combat!
}

// After (FIX): Follower scanning runs always
if (inCombat) {
    // Enemy scanning (unchanged)
}
// Follower scanning now has its own scope block
{
    auto* processLists = RE::ProcessLists::GetSingleton();
    if (processLists) {
        // Follower scanning...
    }
}
```

- **`GetTargetTypeName()` helper** - Added to `GameState.h` for UI display

### Performance Optimization

#### Vitals Polling Optimization for Secondary Targets
- **Primary target (crosshair)**: Always polls vitals at full rate (100ms)
- **Secondary enemies**: Vitals polled at configurable interval (default 500ms), only within distance threshold (default 1024 units)
- **Followers**: Always polled at secondary interval for injured follower detection (configurable via `ALWAYS_POLL_FOLLOWER_VITALS`)
- **Cached vitals**: Non-polled targets retain their last known vitals state

#### Configurable Constants
New `TargetVitalsPolling` namespace in `StateManagerConstants.h`:
```cpp
namespace TargetVitalsPolling
{
    inline constexpr float SECONDARY_VITALS_INTERVAL_MS = 500.0f;  // Polling interval for secondary targets
    inline constexpr float VITALS_POLL_DISTANCE = 1024.0f;         // Distance threshold for polling
    inline constexpr float VITALS_POLL_DISTANCE_SQ = VITALS_POLL_DISTANCE * VITALS_POLL_DISTANCE;
    inline constexpr bool ALWAYS_POLL_FOLLOWER_VITALS = true;      // Always poll followers regardless of distance
}
```
